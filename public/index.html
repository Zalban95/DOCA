MCP servers
Tools from other programs, offered to the {} agent while their server runs.

        

      
What MCP servers are
        Model Context Protocol servers. A running server's tools are offered to the
        agent alongside its built-in ones, named
        mcp__server__tool, and each can be switched off in the harness ⚙ panel.
        Only running servers contribute tools, and nothing is started unless you say so.
        Servers are grouped by the machine they act on: this host, or a paired client — and once
        a client is in play the harness is told which machine each tool reaches, so you can ask
        for something "on my PC" and get the right one.

What may run without asking

    
In Manual the agent asks before it acts; what you always allow is listed below.
What this is
      In Manual the agent is stopped before each tool call that does something, and you
      answer it in the chat. Saying always allow puts the command type on this list — so
      shell: git stops being a question while shell: rm is still asked every time.
      A command that builds itself at run time can never join the list.
      Reading this panel's own state never asks. In Auto nothing is asked, except writing the files that govern the agent and — when the switch below is on — the first action after outside text.

Specialist

    
A helper for one kind of errand, written as a short text file.
What this is
      A specialist is its role plus a few kits (families of tools: files, code, shell, web,
      canvas, memory, devices…); a tool added to a kit later reaches it by itself. Markdown: a front matter
      (name, description, kits, optional tools, model),
      then the role. Claude Code subagent files import as they are. Changing settings, installing, dispatching
      and asking the person are never granted to a specialist.
