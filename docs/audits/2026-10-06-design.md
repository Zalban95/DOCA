# Audit: the panel's visual design (2026-10-06)

Asked 2026-10-06 ("graphically sound"), against CONSTITUTION §7 (U1 protolab.tech is the reference, U2 4K quality,
U3 clean on a dedicated device, U4 phones first-class, U5 nothing overlaps and one style everywhere, U8 delight).
About 170 screenshots of a throwaway panel: 18 pages, 18 Settings sections, the floating chat, `/?view=ambient` and
`/face`, at 1440×900 and 412×915 (DPR 2.6), Classic on dark Default and Modern on light Daylight. **No page errors**
in any configuration and no horizontal page scroll on a phone. Screenshots were kept outside the repository.

Most important first; each ends with its TODO (TODO.md "Audit 2026-10-06").

1. **Docker on a phone hides the containers**: the card is drawn 30 px tall with `overflow:hidden` (inline flex at
   `index.html:536`); image actions clipped; Created wraps into six lines. → No inline flex; one card per row at
   ≤600 px; relative ages.
2. **The floating chat button covers bottom-right controls on most pages** (sdwebui restart, HF folder, Logins ADD,
   grant Add, Slack SAVE, Files delete…), and is a heavy black disc on light themes. → Every page's scroll container
   padded by the button's footprint (today only some, `layout.css:259`); the button follows the theme.
3. **Workstream shows a large black blurred block when idle** (the empty activity overlay). → Hidden until a line
   arrives, faded in; calmer on Daylight.
4. **Harness console header overlaps**: "fallback" over "Pick a model…", the model select cut, the status badge on two
   lines. → The warning on its own line; the select takes the width with ellipsis; one-line badge.
5. **The same action drawn differently**: container actions icon-only on Controls, labelled on Docker; Files colours
   every toolbar button differently. → One button vocabulary (neutral; accent for the card's one primary; red only in
   a confirmation) and one container-action component.
6. **Native unstyled controls** (file picker, radios, range sliders, checkboxes) break U5. → Style them from theme
   tokens (`accent-color`, a `.btn` file button) in both skins.
7. **On/off drawn three ways** (toggle, checkbox, "on" checkbox beside Save). → One toggle for settings that apply at
   once; checkboxes only in forms with a Save.
8. **Long descriptions in all capitals** (Classic: Computers, VMs, MCP, API keys). → Uppercase for titles and labels
   only; descriptions sentence case, muted.
9. **Three page-header patterns** (Computers/VMs/MCP centred button; Archive in a card; Live a bare inline title). →
   One header: title and one line left, actions right.
10. **Empty states differ and some look broken** (bordered vs bare; Projects shows an empty unlabelled select; a new
    floating chat is blank). → One empty state: a dot-of-light glyph, a sentence, one action; a greeting with three
    suggestion chips in a new chat; no select until a project exists.
11. **The phone header wastes space** (search cut to "Search pa"; ⧉ and 📱 beside it). → A search icon that expands;
    ⧉ and 📱 in the ☰ menu.
12. **Modern on a phone shows a grey shadow strip down the left edge** (the closed drawer's shadow). → Shadow only
    while open.
13. **Form rows don't stack on a phone; placeholders carry instructions and get clipped.** → A shared `.form-row`
    wrapping to one field per line under 600 px; labels above inputs.
14. **The Ambient tab inside the panel doesn't fill its space; its talk button and the chat button stack in one
    corner; on Daylight it's a hard black slab.** → Fill the content height; hide the chat button on Ambient and
    `/face`; fade the stage's edges (U2).
15. **"Use this screen" and ✎ on Ambient are nearly invisible; the hint is mono while the screen is sans.** → U3:
    hidden when idle, readable on touch or mouse move; the hint in the screen's font.
16. **`/face` shows "PROTOLAB" in the HUD corner** — the palette's source, not the product. → The product name from
    `/api/branding`, or nothing; credit protolab only in Settings → Voice → The face.
17. **The header repeats the group's name** ("CONTROLS › CONTROLS AMBIENT"). → Rename the first page (Overview) or let
    the group pill open it.
18. **Red ✕/DELETE/REMOVE on every row** reads as alarm against the calm style. → Neutral icons turning red on hover
    or focus, or a ⋯ menu; red in the confirmation.
19. **Sidebar stats wrap and truncate in Classic** (load averages, memory, GPU and model names). → Span both columns or
    smaller tabular figures; full names in tooltips.
20. **Field pages are inset differently** (Connectors and API keys at x≈302, others ≈280). → Strip the settings-panel
    margin when shown as a page.
21. **Inputs larger than the text around them** (Modern harness inputs ~16 px vs 12–13; Users level select in
    Classic). → One `--fs-input` token per skin.
22. **The header search keeps the mono font in Modern.** → The skin's UI font for search and clock.
23. **Heading hierarchy inverted in Channels and Packs** (sub-headings larger than the card title). → Two heading
    levels used everywhere.
24. **Developer section controls scattered; Backups' "☐ on" unexplained.** → "Would it ask?" on its own row with an
    inline result; "Send backups off-site".
25. **Logs filter: 14 greyed "not installed" chips; "Auto" styled differently.** → Only sources installed or with
    lines; "n more" disclosure; one chip style.
26. **MCP catalogue ADD buttons not right-aligned.** → Description `flex:1` with ellipsis; button pinned right.
27. **Files tree toolbar wraps a lone ⬆; colour emoji in a mono interface.** → One row of icon buttons; one monochrome
    icon set tinted by the theme.
28. **The floating chat header is crowded; its open state glows red** (reads as an error). → One-line title, Clear and
    ⚙ in a ⋯ menu, the open state in the accent.
29. **API keys on a phone drops the DOCA apps' Source folder; the device card's controls wrap badly.** → Source as a
    full-width row; "show here [page] ☐ alone [Show]" as one group.
30. **Disabled buttons below readable contrast** (CONNECT, PULL & BUILD, dimmed ▶/■). → ≥3:1 and a tooltip saying why.
31. **Delight, cheaply (U8)**: status dots are flat circles; list pages are plain tables. → Status dots as the face's
    points (sharp core, soft glow, breathing when running); one dot-of-light glyph in empty states; new rows fade in.
32. **`settingsSubNav('<id>')` from outside Settings changes a hidden panel.** → It calls `nav('settings')` first.

**Not checked:** states that need data (a running turn, approval popups, missions, computers, a busy Workstream), the
Terminal with a live PTY, Settings below the first screen, the CLI harness pages, other themes, landscape phones.
