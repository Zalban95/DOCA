# Audit: the three apps against the hub (2026-10-06, hub v2.244.0)

Asked 2026-10-06 ("check if the system is coherent"), against CONSTITUTION §1 (devices are the hive's senses and
hands) and the rule that every capability lands in `/api/v1` first. Read-only: PROTOCOL.md and `modules/api-v1/` on
the hub side; DocaMobile, DocaWear and DocaDesk (`origin/master`, through a temporary worktree since removed) on the
other. Nothing built, run or installed. Repo roots: hub, Mobile, Wear, Desk.

**In one line:** the apps follow the hub, but 2.237–2.244 has not reached them — `quiet` archive events re-notify on
phone and watch (undoing 2.242), phone and desk screenshots never reach the agent, the agent's questions can't be
answered on the phone, the phone's screen tools lack the confirm/sensitive-field guard and are unframed, and Stop /
restart-drop / archive are panel-only while `coverage.js` says otherwise.

Each finding ends with its TODO and the repo it belongs to (TODO.md "Audit 2026-10-06" on the hub; each app's TODO.md).

1. **Archiving finished work re-notifies on phone and watch; `quiet` is ignored.** Hub `missions.js:79-88, 207-233`
   sends `quiet: true` + `archivedAt` (pinned by `test/supervisor.test.js`); Mobile `ProtocolModels.kt:678,699` lack the
   fields and `PushService.kt:165-197` notifies every done/failed; Wear `Harness.kt` likewise and `WatchSession.kt:292-303`
   buzzes on a new event id. Every archive and every quiet automatic reply buzzes. → **Mobile, Wear:** parse `quiet`,
   `archivedAt`, `kind`; never notify when quiet; drop/update archived rows; a captured-frame test.
2. **PROTOCOL and OpenAPI don't describe `archivedAt`, `kind`, `plan`, `progress` on `agent.mission`, nor "quiet +
   archivedAt = remove the row"** (`PROTOCOL.md:517, 534-541`; `openapi.js:299-303`). Root cause of 1. → **Hub:**
   document them; a test that published payload keys match the OpenAPI event schema.
3. **Phone and desk screenshots never reach the agent**: both upload to `/media` and return an id (Mobile
   `PhoneTools.kt:77-91`, Desk `DeskTools.cs:82,147`) that no harness tool reads, while the hub keeps MCP image content
   (`mcp/content.js`) and doca-client returns it. → **Mobile, Desk:** return MCP `image` content.
4. **The agent's questions (`ask_device`) can't be answered on the phone**: notifications without actions
   (`DocaNotificationManager.kt:116-126`), no `doca://prompt` route, `prompt.outcome`/`closed` dropped. The agent waits
   5 min. → **Mobile:** notification actions for the choices (`/prompts/{id}/select` + `/confirm`), a small sheet,
   cancel on closed/outcome.
5. **The phone's screen tools lack the computer's rules the Mobile TODO marks done**: `screen_press` and `input_type`
   have no sensitive classification and no `confirm`; no `cast`, no socket transport; the hub forces a question only
   for `mcp__*__browser_(click|type)` (`approval.js:169`). → **Mobile:** classify the node (as `sensitive()` in
   `clients/computer/tools.js`), refuse password fields, require `confirm` for pay/buy/sign-in/submit, un-tick what is
   not built. **Hub (S11, ask first):** force the question for any device tool called with `confirm: true` or annotated
   sensitive.
6. **Phone and desk content reaches the agent unframed** (trusted unless `openWorldHint`, `mcp/tools.js:62`); no phone
   tool sets annotations, Desk only `readOnlyHint`. A web page on the phone can instruct the agent. → **Mobile, Desk:**
   `openWorldHint: true` on screen, files and clipboard reads.
7. **Stop (2.242), restart/drop (2.243) and "what is working" are panel-only**; `coverage.js`'s `harness` prefix row
   hides it; mission payloads carry no `sessionId`; `workview.js:27-40` maps a stopped work chat to cancelled/done. →
   **Hub:** `POST /api/v1/harness/missions/{id}/stop`, `/harness/work/{id}/restart|drop`, `state: 'stopped'` +
   `stoppedWhy` on work rows; PROTOCOL §23, OpenAPI, the apps' TODOs.
8. **`coverage.js` says devices archive through `/harness`; they can only delete** (`DELETE /harness/sessions/:id` is
   permanent). → **Hub:** `POST /api/v1/harness/sessions/{id}/archive` and `/missions/{id}/archive`; decide what DELETE
   means; coverage checked by capability, not prefix.
9. **The phone pairs with made-up caps** (`CapsBuilder().build()` defaults: 1080×2400, mic and camera false); **Desk
   never re-reports caps** (no `PATCH /devices/me`). Answers are sized wrong and voice/image prompt choices dropped. →
   **Mobile:** real caps at pairing, PATCH on permission change. **Desk:** `PatchOwnCapsAsync` on refresh and monitor
   change.
10. **Desk posts battery samples the hub always rejects** (`not_requested`: `sensors.autoReport` is `[]` and nothing
    sets it). → **Desk:** set `autoReport` at pairing or use `PATCH /devices/me/vars`. **Hub:** show `autoReport` on
    the device page.
11. **The watch relay and watch call bypass the phone's hub-address failover** (`AppContainer.kt:151-167`). →
    **Mobile:** the same `HubFailover` on those clients; a test through `WatchRelay`.
12. **Android Back still leaves the app instead of closing the panel's viewer** (`canGoBack` only refreshed in
    `onPageFinished`). → **Mobile:** `doUpdateVisitedHistory`; check on a phone.
13. **"Queued" (2.148) is read by neither Android app** (`{queued, position}` ignored). → **Mobile, Wear:** parse and show.
14. **DocaMobile and DocaWear share one applicationId**, so the hub can't tell their APKs apart and the watch installs
    any APK whose sha256 matches. A phone APK kept as "docawear" would break the watch. → **Hub:** check a watch mark
    (aapt2 `uses-feature type.watch`) before keeping. **Wear:** refuse an APK without it.
15. **The socket MCP transport (2.202) is used by no first-party app**; the phone serves clear-text HTTP with the
    secret in the path, so a LAN-paired phone has no hands away from that network. → **Mobile, Desk:**
    `wss://<hub>/api/v1/mcp/host` with `transport: "socket"`, HTTP only on the tailnet.
16. **Wear: a paused mission and a stopped work chat buzz as "finished"; archived rows stay listed.** → **Wear:**
    paused = waiting for you; drop archived rows; no notification on cancelled.
17. **The face and schedules need `harness:sessions`, which the watch preset lacks** (`yours.js:38,50-52`,
    `scopes.js:81`). → **Hub (S11 scope change, ask first):** `/face` under `harness:chat`, or the watch preset gains it.
18. **Devices get a `voice` setting but no `/api/v1` route speaks with it** (synthesize/transcribe are panel-only). →
    **Hub:** `POST /api/v1/speech/synthesize|transcribe` with the device's voice, or drop `voice` from device settings.
19. **The `ambient` and `wakeword` coverage notes didn't hold.** *Wake words resolved in 2.245.0* (`GET
    /api/v1/wakeword`, approved). Ambient (weather, plan, notices) still has no v1 twin. → **Hub:** `GET
    /api/v1/ambient`, or say "panel in a web view only".
20. **OpenAPI enums are stale and hand-written** (image `kind` lacks `model`; device kind lacks `channel`, `browser`).
    → **Hub:** derive them from the live registries; extend `openapi.test.js`.
21. **Client test fixtures are ~230 versions old** (Mobile's from hub 2.10.1; Wear's hand-written). → **Hub:**
    `npm run fixtures` writing real frames into `docs/api/fixtures/`; **each app:** load them in parser tests.
22. **The coverage test checks paths, not capabilities** — how 7 and 8 slipped. → **Hub:** per panel group, list the
    actions and require a v1 operationId or a written reason.
23. **Desk listens for `prompt.updated`, which the hub never sends** (real: `prompt.outcome`, `prompt.progress`). →
    **Desk:** handle the real ones.
24. **Mobile parses neither `prompt.closed`/`prompt.progress` nor `mcp.listener`.** → **Mobile:** cancel on closed;
    honour `mcp.listener stop`.
25. **The phone declares no sensors and keys `SensorCap` on `type`, the hub on `id`**, so `sensor.request` to a phone
    always fails. → **Mobile:** `{id, unit, maxRateHz}`, declare accelerometer/light/steps/battery, answer requests.
26. **The phone's push service can be killed after 6 h on Android 15+** (`dataSync`, no `onTimeout`). → **Mobile:**
    handle `onTimeout` or change the service type; test with the activity timeout flags.
27. **The same family has different tool names per client** (Mobile `input_tap`/`input_key`, Desk
    `input_click`/`input_keys`, doca-client its own). One skill can't name "click" everywhere. → **Hub:** a canonical
    family → tool-name table in PROTOCOL §22.1; then align the apps.
28. **The apps' "From the hub" TODO sections are behind** (Wear stops at 2.202, Desk at 2.234, Mobile lacks 2.242 and
    2.244) and some ticked items aren't in the code. → **Each app:** the missing sections, written from the hub side;
    un-tick what isn't built.
29. **Mobile refuses any hub whose protocol isn't exactly "1.0"** (ignores `minClient`). → **Mobile:** accept when
    `minClient ≤ 1.0 ≤ version`.
30. **Wear's LAN pairing hard-codes port 4242.** → **Wear:** take it from the address or the pair offer.
31. **Cross-repo contracts are tested on one side only** (the pair offer in Mobile only; the `window.DocaDevice` bridge
    nowhere; the phone's MCP server shape nowhere). → **Hub:** `test/client-contracts.test.js` pinning them.

**Not checked:** real devices; the Gradle and .NET suites (not run); Desk's working branch (only `origin/master`).
